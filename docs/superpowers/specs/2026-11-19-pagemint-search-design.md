# PageMint Web Search — Design

Date: 2026-11-19
Status: draft, awaiting approval (builder check done)
Scope: project 3 of 3. Adds a `search` tool to PageMint.

## Intent and why

Harsha's agents use Firecrawl's search "sometimes" and hit its limits.
PageMint should offer web search too, free to run and usable by everyone.
Research (2026-11-19) found no general web search that is at once free,
keyless and allows bots: DuckDuckGo/Google pages forbid scraping; APIs
(Tavily, Brave, Exa) need a key; SearXNG is free and keyless but must be
self-hosted. Harsha chose option C: support both a self-hosted SearXNG and
the user's own API key, behind one tool. Later, a paid hosted PageMint can
include search with Harsha's own key (a selling point).

## Goals

- One MCP tool `search(query, ...)` returning titles, URLs and snippets.
- Works with whatever the user configured: SearXNG (free, unlimited) or a
  key for Tavily or Brave. Optional: fetch the top results' pages as
  Markdown in the same call (like Firecrawl's search + scrape).
- Never calls a paid service unless the user configured its key. Never
  scrapes search-engine result pages.
- Same safety as the rest of PageMint; keys never leak.

## Non-goals

- Scraping DuckDuckGo, Google, Bing or any search result page.
- Shipping or sharing any API key; a hosted search service.
- News/image/video search, answers/summaries generated by a provider.

## Anti-goals

- A key appearing in logs, errors, tool output, or requests to other hosts.
- The SearXNG exception becoming a way to reach other private addresses.
- Silent fallback to a provider the user did not configure.

## Approaches considered

- **A. Bring your own key only** (Tavily/Brave/Exa): easy, but every user
  needs an account and lives with that provider's monthly limit.
- **B. SearXNG only:** free and unlimited, but needs Docker; heavy use can
  get SearXNG's upstream engines to block it.
- **C. Both, behind one tool — chosen.** SearXNG when configured, else the
  first configured key; clear setup help when nothing is configured.

## Configuration (environment variables only for keys)

| Variable | Meaning |
|---|---|
| `PAGEMINT_SEARXNG_URL` | Base URL of the user's SearXNG, e.g. `http://localhost:8888` |
| `PAGEMINT_TAVILY_API_KEY` | Tavily key |
| `PAGEMINT_BRAVE_API_KEY` | Brave Search API key |
| `PAGEMINT_SEARCH_PROVIDER` | Optional fixed choice: `searxng`, `tavily`, `brave` |
| `PAGEMINT_SEARCH_FALLBACK` | `1` to allow trying the next configured provider when the chosen one fails (off by default) |

Keys live in `Settings` as secret fields: excluded from `repr`, never put in
results, warnings or errors. Keys come **only from environment variables**
(never CLI flags, which show up in process lists and shell history, and
never from tool arguments). The CLI has `--provider` and `--searxng-url`.

## Tool

`search(query, limit=10, fetch_pages=0, provider="auto")`

- `limit`: 1–20 results. `fetch_pages`: 0–5; when > 0 the top N result
  URLs are fetched with the core scrape (robots.txt, rate limit, SSRF and
  size rules all apply) and returned as Markdown (20,000 chars each).
- `provider`: `auto` or one of the three names (must be configured).
- Choosing: a `provider` argument other than `auto` wins; else
  `PAGEMINT_SEARCH_PROVIDER`; else SearXNG if its URL is set; else Tavily,
  then Brave — the first with a key.
- **No automatic fallback by default** (it could quietly move a user from
  free SearXNG to a key that costs money). On failure the error names the
  other configured providers and how to pick one. With
  `PAGEMINT_SEARCH_FALLBACK=1`, and only when the provider was not pinned
  (argument or `PAGEMINT_SEARCH_PROVIDER`), any failure of the chosen
  provider — connection refused, timeout, 429, 5xx — tries the next
  configured one, with a warning naming both.
- Returns:
```
{ "query", "provider",
  "results": [{"title", "url", "snippet", "published": ISO date|null}],
  "pages": [{"url", "title", "markdown"} | {"url", "error"}],   # only with fetch_pages
  "warnings": [...] }
```
- Nothing configured → error type `not_configured` whose message gives the
  two ways to set it up (SearXNG Docker command; or a key variable).
- Result URLs are normalised; non-http(s) results dropped; duplicates
  removed. Titles/snippets are returned as plain text (provider HTML
  stripped). They are untrusted page text, like any scraped content.

## Providers (API shapes from the providers' public docs, recalled; to be
verified against the docs at build time — tests use fake servers)

- **SearXNG:** `GET {base}/search?q=...&format=json` (JSON output must be
  enabled in SearXNG's `settings.yml`: `search: formats: [html, json]`;
  without it SearXNG answers 403 — PageMint's error says how to enable it).
  Results: `results[].{title,url,content,publishedDate}`.
- **Tavily:** `POST https://api.tavily.com/search`, `Authorization: Bearer
  <key>`, body `{"query", "max_results"}` → `results[].{title,url,content,
  published_date}`.
- **Brave:** `GET https://api.search.brave.com/res/v1/web/search?q=&count=`,
  header `X-Subscription-Token: <key>` → `web.results[].{title,url,
  description,page_age|age}`.
- **Exa: not included.** Its search returns no snippet text unless page
  contents are requested, which Exa bills extra per result. Can be added
  later if wanted.

## Safety

- All provider calls go through the core fetcher (SSRF guard, rate limit,
  size and time limits). The core fetcher gains a `headers` argument; for
  calls carrying a key, **redirects are not followed** (a redirect is an
  error), so a key can never be forwarded to another host.
- Provider base URLs for Tavily/Brave are fixed `https://` constants.
- **SearXNG on localhost:** the private-address block would refuse
  `http://localhost:8888`. Exception: the exact origin (scheme, host,
  port) of `PAGEMINT_SEARXNG_URL`, which only the user can set, is allowed
  for the search call, even when private. Redirects from it are not
  followed. Nothing else (result URLs, `fetch_pages`) gets the exception.
- robots.txt: calls to the two fixed provider API endpoints, made with the
  user's own key under that provider's API terms, are not robots-checked
  (robots.txt governs crawling, not keyed API use, and a robots.txt hiccup
  must not break search). SearXNG (the user's own server) is not
  robots-checked either. Everything else — including every page fetched
  through `fetch_pages` — is robots-checked as usual.
- Keys are redacted from any exception text before it becomes an error
  message (defence in depth).

## CLI

`pagemint search "query" [--limit N] [--fetch N] [--provider NAME] [--json]`
prints results as `title — url` lines with snippets, or JSON.

## Decisions made by Claude (check these)

- `auto` prefers SearXNG (free, unlimited) over keys, then Tavily (free
  tier without a card per third-party comparisons), then Brave.
- No automatic fallback unless `PAGEMINT_SEARCH_FALLBACK=1` (safety: no
  silent switch to a key that may cost money).
- Keys only via environment variables, never CLI flags.
- Exa left out (snippets cost extra).
- Keyed provider API calls and the user's SearXNG skip robots.txt;
  everything fetched from results is robots-checked.
- `fetch_pages` max 5; `limit` max 20.
- SearXNG's own origin is the only private address the search call may
  reach, and only because the user configured it.
- Keyed calls never follow redirects.
